1. RetroBar  (main attribution)
--------------------------------------------------------------------------------

The XAML layout and the structural approach of the theme used by Win7Taskbar are
inspired by / derived from RetroBar.

    Project : RetroBar
    Author  : dremin
    Site    : https://github.com/dremin/RetroBar
    License : Apache License, Version 2.0

Derived works and scope of the attribution:

  * Themes/Windows7.xaml
    A RetroBar skin, included in Win7Taskbar AS IT IS (byte-identical to the
    original, MD5 1bf56a8e4d67107acdbbd9440e0a320a). It comes from the
    Windows7RetrobarTheme repository and is itself a derived work of RetroBar:
    it extends its styles through BasedOn and references its types.

  * src/RetroBar.Shim/
    A compatibility assembly named "RetroBar". The theme declares
    xmlns:controls="clr-namespace:RetroBar.Controls;assembly=RetroBar" and
    therefore requires an assembly with that name. ONLY the public surfaces
    (type and property names) needed to resolve the theme bindings are
    replicated:
        RetroBar.Controls.NotifyIcon        (IsPinned, Host)
        RetroBar.Controls.NotifyIconList    (NotificationArea, PinnedIcons)
        RetroBar.Converters.BoolToVisibilityConverter
        RetroBar.Utilities.Settings         (Instance, CollapseNotifyIcons)

EXPLICIT STATEMENT ABOUT THE SOURCE CODE
    NO line of RetroBar's C# source code was copied verbatim into this project.
    All the logic (Superbar grouping, jump lists, notification area, AppBar
    behaviour) was REIMPLEMENTED FROM SCRATCH in native C++, under native/.
    What is taken from the RetroBar project:
      - the XAML theme file listed above, an existing derived work;
      - the public type/member names that the XAML bindings require;
      - the ALGORITHMS of a few features described below, reimplemented as
        original code but following the same logic.

  * src/Win7Taskbar/Controls/TaskThumbnail.cs
    Live window previews through the DWM APIs. It follows the logic of
    RetroBar/Controls/TaskThumbnail.cs: registering the thumbnail with
    DwmRegisterThumbnail, using DWM_TNP_SOURCECLIENTAREAONLY, querying the
    source size with DwmQueryThumbnailSourceSize, fitting it to the maximum
    size (180x120) while preserving the aspect ratio, expressing the
    destination rectangle in physical pixels and updating it every frame, and
    calling DwmUnregisterThumbnail when the control goes away.
    Original code, derived algorithm. Apache 2.0.
    NOTE (v2.56): the feature is currently disabled - the popup is not opened
    and both implementations are kept, commented out, as a reference. See the
    README for the user-facing statement.

  * src/Win7Taskbar/Converters/ToolTipOffsetConverters.cs
    Positioning of the preview relative to the edge occupied by the taskbar
    (horizontal/vertical offset and PlacementMode). Same logic as the
    converters with the same name in RetroBar/Converters/. Apache 2.0.

  * native/src/FlyoutLauncher.cpp  (second path: Aero Clock fallback)
    Opening the system calendar (Aero Clock). It follows the logic of
    RetroBar/Utilities/ClockFlyoutLauncher.cs: creating the COM object with
    CLSID A323554A-0FE1-4E49-AEE1-6722465D799F, choosing between the
    IAeroClock interface (7A5FCA8A-..., Windows 8 and later, first parameter
    HWND) and IAeroClockLegacy (4376DF10-..., Vista/7, first parameter
    integer), calling ShowFlyout with the taskbar rectangle, and then
    correcting the position of the "ClockFlyoutWindow" window by snapping it to
    the edges (15 px threshold, 7 px margin) and keeping it inside the work
    area. Original C++ code, derived algorithm. Apache 2.0.

  * native/src/ImmersiveFlyouts.cpp / .h  (first path: modern flyouts)
    Opening the real Windows 10/11 flyouts for network, clock, battery and
    volume. The invocation sequence is ADAPTED FROM ExplorerPatcher (see
    section 3); previously it was only conceptually derived, with ManagedShell
    (see section 4) as the reference for the shape of the interfaces:
      - creating CImmersiveShell (C2F03A33-21F5-47FA-B4BB-156362A2F239);
      - IServiceProvider::QueryService towards the experience manager factory
        (2E8FCB18-A0EE-41AD-8EF8-77FB3A370CA5);
      - GetExperienceManager with the runtime name of the desired flyout
        ("Windows.Internal.ShellExperience.TrayClockFlyout" for the clock,
        "...MtcUvc" for the volume) and QueryInterface on the matching IID;
      - calling ShowFlyout with the taskbar rectangle (a
        Windows.Foundation.Rect, four floats, passed by reference), preceded by
        AllowSetForegroundWindow on the shell process so that the flyout appears
        and receives input.
    The COM interfaces are redeclared in C++ from their binary shape (vtable).
    From ManagedShell: the shape of the interfaces. From ExplorerPatcher: the
    sequence, the GUIDs and the runtime names, including the network and battery
    ones. GPL-3.0-or-later.

  * native/src/ExplorerTrayReader.cpp
    Reading the icons already present in the Explorer notification area, to fill
    the taskbar at startup. Algorithm derived from ManagedShell,
    src/ManagedShell.WindowsTray/ExplorerTrayService.cs (see section 4):
      - locating the toolbars Shell_TrayWnd > TrayNotifyWnd > SysPager >
        ToolbarWindow32 and, for the hidden icons, the
        NotifyIconOverflowWindow window;
      - counting the buttons with TB_BUTTONCOUNT and reading each one with
        TB_GETBUTTON, allocating the exchange structure in Explorer's address
        space (VirtualAllocEx) and reading it back with ReadProcessMemory,
        followed by a second read at the address in the dwData field to obtain
        the icon data;
      - the TBSTATE_HIDDEN (8) state to tell hidden icons apart;
      - temporarily disabling automatic grouping through the TrayNotify COM
        object (25DEAD04-1EAC-4911-9E3A-AD0A4AB560FD, interfaces ITrayNotify on
        Windows 8+ and ITrayNotifyLegacy on 7), restored when the read is over.
    Original C++ code, derived algorithm. Apache 2.0.

  * Task button behaviours in src/Win7Taskbar/TaskbarWindow.xaml.cs
    Interaction rules taken from RetroBar/Controls/TaskButton.xaml.cs:
      - clicking a window that is already in the foreground minimises it; the
        condition has to be evaluated on button DOWN, not on release;
      - releasing the foreground right with SendInput on an unassigned virtual
        key before activating someone else's window;
      - mouse wheel: up activates, down minimises;
      - middle click opens a new instance of the application.
    Reimplemented as original code. Apache 2.0.

3. ExplorerPatcher  (direct derivation, GPL compatible)
--------------------------------------------------------------------------------

    Project : ExplorerPatcher
    Author  : Valentin Radu (valinet) and contributors
    Site    : https://github.com/valinet/ExplorerPatcher
    License : GNU General Public License v2 (no version indication in the source
              files, so the "any version ever published by the FSF" clause
              applies)

Since Win7Taskbar moved to GPL-3.0, ExplorerPatcher's code can be used as a direct
source, no longer just as inspiration: GPL-2.0 "or later" allows redistributing the
derived work under GPL-3.0, which in turn is compatible with RetroBar's Apache-2.0.

What was adapted, file by file:

  * native/src/ImmersiveFlyouts.h and native/src/ImmersiveFlyouts.cpp
    from ExplorerPatcher/ImmersiveFlyouts.h and ImmersiveFlyouts.c
      - the COM call sequence: CoCreateInstance(CLSID_ImmersiveShell,
        CLSCTX_NO_CODE_DOWNLOAD | CLSCTX_LOCAL_SERVER, IID_IServiceProvider)
        -> QueryService(CLSID_ShellExperienceManagerFactory)
        -> GetExperienceManager(runtime name)
        -> QueryInterface(IID of the flyout)
        -> ShowFlyout / HideFlyout;
      - the four runtime names (NetworkFlyout, TrayClockFlyout,
        TrayBatteryFlyout, MtcUvc) and their IIDs
        (C9DDC674-..., B1604325-..., 0A73AEDC-..., 7154C95D-...);
      - the use of WindowsCreateStringReference with HSTRING_HEADER instead of
        WindowsCreateString;
      - the shape of the IExperienceManager and IShellExperienceManagerFactory
        interfaces (IInspectable plus specific methods).

    Rewritten from scratch instead:
      - resource management, with RAII wrappers (ComPtr, HStringRef) replacing the
        manual release nested in if(SUCCEEDED(hr)) blocks;
      - CACHING of the factory and of the experience managers between calls (the
        original creates and releases them on every invocation), with a second
        attempt on an emptied cache to survive an Explorer restart;
      - runtime loading of combase.dll with GetProcAddress, so the DLL also loads
        on Windows 7 where that module does not exist;
      - error propagation, crossing the DLL boundary as return values and not as
        exceptions;
      - the interface declarations, in C++ with virtual methods instead of
        explicit C vtables.

    One correction with respect to the original: in ExplorerPatcher's header
    GetExperienceManager declares the first parameter as HSTRING* but receives an
    HSTRING; the correct signature is used here, by value.

  * native/src/FlyoutLauncher.cpp
    delegates the immersive path to ImmersiveFlyouts; the Aero Clock fallback and
    the flyout position correction remain derived from RetroBar (section 1).

  * native/include/Win7TaskbarCore.h
    the numeric values of W7T_FLYOUT_* and W7T_FLYOUT_SHOW/HIDE mirror
    ExplorerPatcher's INVOKE_FLYOUT_*, so the value crosses the DLL boundary
    without a translation table.

The jump-list and button-grouping behaviour remains CONCEPTUALLY inspired by
ExplorerPatcher, as does the idea of reusing the system flyouts through
ImmersiveShell, publicly described by the author in:
    https://valinet.ro/2021-11-18/Functional-Windows-10-flyouts-on-Windows-11.html

The GUIDs are interoperability identifiers for system COM interfaces: facts about
the Windows API, not protected creative material.

The English summary of this section, with the file-by-file table, is in
THIRD-PARTY-NOTICES.md.

4. ManagedShell  (notification area and system flyout algorithms)
--------------------------------------------------------------------------------

    Project : ManagedShell
    Author  : Cairo Shell contributors (cairoshell)
    Site    : https://github.com/cairoshell/ManagedShell
    License : Apache License 2.0 (full text in the appendix)

ManagedShell is the library RetroBar is built on. The ALGORITHMS of two parts of
this project derive from it:

  * native/src/ExplorerTrayReader.cpp
    from src/ManagedShell.WindowsTray/ExplorerTrayService.cs and TrayNotify.cs

  * native/src/FlyoutLauncher.cpp  (the modern flyouts part)
    from src/ManagedShell.UWPInterop/ImmersiveShellHelper.cs and the declarations
    in src/ManagedShell.UWPInterop/Interfaces/

What was derived in detail is described in section 1. In both cases this is C++
code written from scratch: what was taken from the C# source is the sequence of
system calls and the COM identifiers, not the text of the program.

5. Aero Tray  (Windhawk mod by aubymori - overflow panel layout)
--------------------------------------------------------------------------------

    Project : Aero Tray (Windhawk mod)
    Author  : aubymori
    Site    : https://github.com/aubymori (windhawk-mods repository)
    License : GNU GPL-3.0 (the licence Windhawk mods are distributed under)

What was adapted (v2.2, files src/Win7Taskbar/TaskbarWindow.xaml and
TaskbarWindow.xaml.cs):

  * the overflow panel metrics at 96 DPI: the "Customize" link area is 43 px high
    with 16 px padding, 7 px padding around the icon area, 18 px between icons,
    8 px offset of the flyout from the monitor edges; in WPF the values are in
    DIPs and already scale with the DPI (the equivalent of the mod's
    MulDiv(value, dpiY, 96));
  * the fixed grid of 3 icons per row (Windows 7/8 behaviour, not the 2-per-row
    of Windows 10/11);
  * the hover/pressed states of the "Customize..." link and the Control Panel
    path used to open it:
    shell:::{26EE0668-A00A-44D7-9371-BEB064C98683}\0\::{05D7B0F4-...}.

What was NOT ported: the whole symbol hooking part (SYMBOL_HOOK, *_orig,
HookSymbols, Wh_ModInit, PatchStartIsBack). The mod hooks explorer.exe's internal
classes, while Win7Taskbar draws its own UI and has nothing to hook. The layout
logic was rewritten in WPF/C# (Popup + styles + global mouse hook for closing),
not copied.

5bis. ViGlance and ExplorerEx  (v2.3 references, no code copied)
--------------------------------------------------------------------------------

  * ViGlance (lee-soft, github.com/lee-soft/ViGlance): reference for refreshing the
    battery icon immediately from the real power state (GetSystemPowerStatus) when
    Explorer's legacy toolbar stays frozen on Windows 10/11. No VB6 source copied.
  * ExplorerEx (kfh83, github.com/kfh83/ExplorerEx): inspiration for the Address /
    Links / Desktop bands, reimplemented as a WPF layer on top of public shell
    APIs. No source copied.
